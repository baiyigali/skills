# 网站健康体检报告（Website Health Report）

对用户提供的网址执行深度体检，产出与专业机构同等规格的正式报告（HTML + PDF）。
本技能沉淀自 20 个真实站点、两批正式交付的实战流程，**核心价值不是扫描，而是"正式报告"**：证据、影响、修复方向、FAQ、版式一个不少。

## 流程总览（7 步，顺序执行）

### 第 1 步：输入解析
- 接受域名（`example.com`）或完整 URL。
- 从 URL 提取域名；机构名/行业若无法从页面推断，**问用户**（机构名会出现在报告标题与文件名中）。
- 用户提供多个网址时，逐个独立走完全流程（不合并报告）。

### 第 2 步：深度体检（脚本）
```bash
python3 <skill>/scripts/audit.py <域名或URL> -o /tmp/audit_<域名>.json --org "机构简称" --industry "行业"
```
- 覆盖：DNS 存活、HTTPS 证书（subject/issuer/有效期）、HTTP 跳转、HSTS、title/description/H1/viewport/编码、robots/sitemap/404 行为、版权年份、ICP、加载耗时、建站指纹。
- **内页抽查**：默认共约 10 页——首页必查，脚本自动按内容价值抽取内页（新闻/案例/详情页优先）。
- `checks.render_hint` 出现 `JS_RENDER_SHELL_SUSPECT` 时，脚本（curl）拿到的内容不可信，**必须用浏览器自动化实测**（打开首页与关键内页，人工记录标题、栏目、最新文章日期等证据），再进入分析。

### 第 3 步：证据纪律（硬性，不可跳过）
逐条遵守 `references/措辞与证据纪律.md`，要点：
- **只读检测**：不登录、不提交表单、不做任何注入测试。
- **每条证据必须是实测原文**：证书 CN 原文、页面标题原文、版权行原文、具体日期——不写「可能」「疑似」式的模糊断言；无法判定的项目直接不写。
- **JS 渲染壳站点的声明必须来自浏览器实测**，不能用 curl 快照。
- 证书类结论注意区分：443 无响应 ≠ 证书过期；共享证书/CDN 默认证书是常见形态，写清签发给谁。

### 第 4 步：问题分析（智能体撰写）
从 audit JSON + 浏览器实测中提炼 3-5 个最有说服力的问题，写成 issues JSON：

```json
{
  "domain": "www.example.com", "org": "机构简称",
  "full_name": "机构全称", "industry": "行业",
  "finding": "核心问题一句话（放结论摘要）",
  "extra": "补充说明，可为空（例如肯定对方做得好的地方）",
  "checks_total": 24,
  "issues": [
    {"title": "问题标题", "evidence": "检测证据（实测原文）",
     "impact": "对您的影响（结合该机构的客户与业务场景写）", "fix": "修复方向（具体到怎么改）",
     "severity": "高|中|低"}
  ]
}
```

写作要求：
- `impact` 是报告的灵魂：**必须联系该机构的实际业务场景**（面向什么客户、客户会怎么接触到网站），不要写泛泛的「影响用户体验」。
- `fix` 要具体可执行（「在 DNS 中将 @ 记录解析到与 www 相同服务器并 301 跳转」而不是「修复域名解析」）。
- 严重度标准：高=直接造成信任伤害或客户流失（明文/证书错误/域名被接管）；中=影响排名与观感（H1/viewport/404）；低=维护性改善（版权年份/sitemap）。
- **不写内部编号**（A1/E2 之类只用于你自己组织材料，绝不出现在任何输出里）。

### 第 5 步：生成报告 HTML
```bash
python3 <skill>/scripts/gen_report.py /tmp/audit_<域名>_report.json /tmp/网站体检报告-<机构名>.html
```
- 记下脚本输出的 `FILENAME_SUGGEST`，PDF 文件名必须用它。
- 用户明确不要品牌块时加 `--brand none`。

### 第 6 步：出稿前复测（防乌龙，不可跳过）
1. **交叉复测**：对报告里每一条证据声明，重新执行对应检测（curl/浏览器），确认原文一致、证书日期一致；有出入的立即修正报告。
2. **数字核对**：结论摘要与主题句里的问题数量必须与 issues 条数一致（逐项重数）。
3. **措辞扫描**：对 HTML 全文扫描禁词（漏洞、攻击、渗透、失守、黑客、入侵、被黑），零命中才算过。
4. **编码扫描**：确认 HTML/PDF 无内部编号残留（搜 `【A`、`【B`、`【C`、`【D`、`【E` 应为零命中）。

### 第 7 步：生成 PDF 并交付 + 对话反馈
```bash
python3 <skill>/scripts/html2pdf.py /tmp/网站体检报告-<机构名>.html /tmp/网站体检报告-<机构名>.pdf
```
- **交付文件名固定为「网站体检报告-机构名.pdf」**（不用裸的「体检报告-」）。
- 交付 HTML + PDF 两个文件（HTML 供快速预览，PDF 供转发/打印）。
- 用 present_files 交付。
- **交付后必须在对话里给用户一段简短反馈**（检测完不算完，反馈才算完），包含：
  1. 检出几个问题，按严重度分级（X 项较严重 / Y 项中等 / Z 项改善项）；
  2. 核心发现一句话（与报告结论摘要一致）；
  3. 每个问题一行式要点（编号 + 问题 + 关键证据数字/日期）；
  4. 复测与扫描结果（交叉复测是否全部成立、禁词/编码是否零命中）；
  5. 交付文件的位置与命名。
- 反馈要克制：不重复报告全文，不写大段分析，5-10 行以内；有值得肯定的加分项（如 robots 配置规范）也点一句。

## 字体策略（html2pdf.py 已内置探测，此处供排障）
| 系统 | 正文 | 标题/加粗 |
|---|---|---|
| macOS | `/Library/Fonts/Arial Unicode.ttf`（11.5pt） | `/System/Library/Fonts/STHeiti Medium.ttc`（15pt） |
| Windows | `C:\Windows\Fonts\msyh.ttc` 微软雅黑（11.5pt） | `C:\Windows\Fonts\msyhbd.ttc`（15pt） |
| Linux | Noto Sans CJK / 思源黑体（自动探测，11.5pt） | 同左 Bold（15pt） |
| 找不到 | **报错退出**，提示安装 `fonts-noto-cjk`，绝不缺字硬出 | — |

依赖：fpdf2（`pip install fpdf2`，建议装在独立 venv）。

## 品牌配置
- 默认读取技能根目录 `brand.json`（品牌名、官网、联系方式、关于块、封面声明）。
- 品牌出现在三处：封面出品行、报告末尾「关于」块、每页页脚。
- 用户不想要品牌：一句话即可，加 `--brand none`（封面、关于块、页脚三处一并消失，其余版式不变）。
- 想换品牌信息：改 brand.json 或传 `--brand-file` 指向其他 JSON。

## 边界（本技能不做）
- 不发邮件、不挖联系方式、不管理候选名单、不做任何触达动作。
- 不做侵入性测试（登录/表单提交/注入）。
- 不对报告结论做法律背书（报告已声明基于公开信息层面检测）。
