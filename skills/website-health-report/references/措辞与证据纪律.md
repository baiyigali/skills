# 措辞与证据纪律（网站体检报告）

> 本纪律来自 20 个真实站点、两批正式交付的实战教训。违反任何一条都可能造成「乌龙报告」——对客户信誉和自身专业性的伤害都是不可逆的。

## 一、措辞红线

### 禁用词（发送/交付前全文扫描，零命中才许出稿）

| 禁用 | 替代 |
|---|---|
| 漏洞 | 技术问题 / 配置缺陷 / 风险点 |
| 攻击 / 被攻击 | 风险暴露 / 安全隐患 |
| 渗透 / 渗透测试 | 深度检测 |
| 失守 / 被黑 / 被入侵 | 已脱离贵方控制 / 被第三方接管 |
| 黑客 | 第三方 / 未经授权的访问者 |

### 措辞原则
1. **恐吓不产生信任**：说服力来自「信任伤害 + 同行比较 + 排名流失」，不来自吓唬。
2. **不确定的不写**：禁止「可能」「疑似」式断言进入结论；无法判定的项直接不写，或标注「需人工复核」。
3. **不摆姿态**：不说「贵司安全意识薄弱」类评判，只摆证据和影响。
4. **投递/触达过程信息一律不进报告**：报告读者手里已经有报告了，「因未找到邮箱故…」之类的注是败笔。

## 二、证据纪律

1. **只读检测**：GET/HEAD 请求、证书握手、公开快照。不登录、不提交表单、不做注入、不测爆破。
2. **证据必须是实测原文**：
   - 证书：写 CN/签发者原文 + 精确过期日期（如「证书签发给 *.cdn.myqcloud.com，2023-11-25 过期」）；
   - 页面：标题/版权行/文章日期引用原文（如页面标题「问鼎娱乐官方网页版网站入口」）;
   - 状态码：robots/sitemap/404 各自的实测返回码。
3. **区分相近现象**（历史上各踩过一次）：
   - 「443 无响应」≠「证书过期」——先区分 TCP 不通 / TLS 握手失败 / 证书错误三种情形；
   - 共享证书、CDN 默认证书（如 *.cdn.myqcloud.com）是常见形态，写清「签发给谁」而不是笼统说「证书错误」；
   - JS 渲染壳站点（凡科 col.jsp 等）curl 拿不到真实内容，**声明必须来自浏览器实测**。
4. **时变声明要在出稿前复测**：证书可能刚换、301 可能刚修。出稿前对每条证据重新执行检测（交叉复测），有出入立即修正。
5. **数字一致性**：结论摘要、正文、FAQ 引用的问题数量必须一致（逐项重数，历史上曾 9/10 封主题行数字错误）。

## 三、报告内容边界

1. **内部编号永不上报告**：【A1】【E2】等编码只用于内部组织文案（注意复合形式【A1/A2】容易漏删）。
2. **只写与体检对象相关的事**：不写检测者自己的流程困境。
3. **补一句肯定**：对方做得好的地方（如内容更新勤、栏目结构清晰）在 extra 里点一句——报告可信度反而更高。
4. **修复方向要照单可执行**：读者拿给任何技术人员都能直接动手，这是「不强求合作」定位的说服力来源。
